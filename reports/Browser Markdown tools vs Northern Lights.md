# No browser-only rival beats Northern Lights overall

No browser-only Markdown tool found in this research is better than Northern Lights MD Viewer overall, at least for its core job: reading a folder of real `.md` files comfortably, editing them, and saving them back in place with clean diffs, all offline from one file with nothing installed. Several tools are better in specific ways. **MarkView** (a Chrome extension) is a richer viewer, with KaTeX math, PlantUML/Graphviz, DOCX export and search across a folder. **vscode.dev** is a far stronger source editor. **TiddlyWiki** has a decade of maturity and a plugin ecosystem. **Markdeep and TeXMe** render LaTeX math that Northern Lights cannot. But every one of them fails at least one of four things Northern Lights does at once: edit the original `.md` in place, run with no network, need no install, and give a reading-first experience. Under a strict "no IT approval" bar the field shrinks to almost nothing. Extensions are installs. Hosted editors send your content's code path through a third-party origin. Most small single-file tools quietly load from a CDN. Only the self-contained wikis (TiddlyWiki, Feather Wiki) pass as shipped, and they store content inside the wiki file rather than in `.md` files. The gap that matters most is **math rendering**: every serious alternative in every category now has it, and Northern Lights does not. Next come **search across files** and **spellcheck**. True WYSIWYG and plugins matter less for a tool built to read first.

## Four classes of tool, and none combines in-place saving with zero network

The candidates fall into four groups, and each one gives up something different. **Single-file HTML tools** are the only group that shares Northern Lights' deployment model. **Hosted web apps and PWAs** (vscode.dev, StackEdit, Dillinger, HedgeDoc, plus a long tail of File System Access apps) are loaded from a vendor's origin over the network ([VS Code for the Web](https://code.visualstudio.com/docs/setup/vscode-web); [StackEdit](https://github.com/benweet/stackedit)). **Browser extensions** are viewers only. None of the five leading ones edits or saves back to the source file ([simov/markdown-viewer](https://github.com/simov/markdown-viewer); [MarkView listing](https://chromewebstore.google.com/detail/cfopbpknalachedpcddhgbgjoigklien)). **Installed desktop apps** are the reference points, and every one of them requires installing an executable.

| Candidate | Deployment | Edits original `.md` in place | Offline as shipped | Math | Passes strict no-IT bar |
|---|---|---|---|---|---|
| **Northern Lights** | One HTML file, file:// | Yes, splices only the changed block (Chromium) | Yes, Mermaid vendored | **No** | **Yes** |
| TiddlyWiki 5 | One HTML file | No, content lives in tiddlers inside the wiki | Yes | Probably (KaTeX plugin file present) | Yes |
| Feather Wiki | One HTML file, ~56 KB | No, saves by download or WebDAV | Yes | Not found | Yes |
| Markdeep / TeXMe | Script wrapper around a `.md.html` | No editor | Only if scripts are vendored | Yes | Only after vendoring |
| EdgeMD Viewer | One HTML file | Yes, whole file | **No**, loads marked/DOMPurify from cdnjs | No | No |
| orz-mdhtml | Node CLI generates `.md.html` | Rewrites the embedded copy, not your `.md` | **No**, even `--inline` uses a CDN | Yes | No |
| vscode.dev | Hosted Microsoft site | Yes, whole buffer (Chromium) | Undocumented | Not verified for web | Borderline |
| StackEdit / Dillinger | Hosted site or self-hosted server | No, browser storage plus cloud sync | After first load | StackEdit yes | No |
| MarkView (extension) | Chrome Web Store install | No, view and export only | Yes | Yes | No |
| Markdown Viewer (simov) | Chrome Web Store install | No | Yes | Yes (MathJax) | No |

Sources for the table: [TiddlyWiki markdown plugin](https://github.com/Jermolene/TiddlyWiki5/tree/master/plugins/tiddlywiki/markdown), [Feather Wiki](https://codeberg.org/Alamantus/FeatherWiki), [Markdeep](https://casual-effects.com/markdeep/), [TeXMe](https://github.com/susam/texme), [EdgeMD](https://github.com/0xedgelessblade/edge-md-viewer), [orz-mdhtml SKILL.md](https://cdn.jsdelivr.net/npm/orz-mdhtml@0.9.3/orz-mdhtml-skills/SKILL.md), [VS Code for the Web](https://code.visualstudio.com/docs/setup/vscode-web), [Dillinger](https://dillinger.io/), [NoteLoom comparison (vendor)](https://noteloom.cc/blog/browser-based-local-first-markdown-editors/), [MarkView](https://chromewebstore.google.com/detail/cfopbpknalachedpcddhgbgjoigklien), [simov](https://github.com/simov/markdown-viewer).

The table shows the pattern. Tools that save in place need the network. Tools that are offline do not save `.md` files in place. The only tool that does both is Northern Lights.

## Single-file HTML tools match the deployment but not the job

**TiddlyWiki 5** is the most serious candidate in Northern Lights' own class. It is actively maintained (v5.4.1, July 2026), and its official Markdown plugin is built on markdown-it with extra plugins ([GitHub releases](https://github.com/Jermolene/TiddlyWiki5/releases); [markdown plugin](https://github.com/Jermolene/TiddlyWiki5/tree/master/plugins/tiddlywiki/markdown)). Where it is better: maturity, community, extensibility, and probably math. A `markdown-it-katex.js` file ships in the plugin folder, though the readme does not advertise it. Where it is worse is fundamental. It solves a different problem: a personal wiki stored inside one HTML file, not a viewer for a git repo of `.md` files. Its in-place saving through the File System Access API is officially labelled **"somewhat experimental"** ([tiddlywiki.com](https://tiddlywiki.com/static/Saving%2520on%2520Browser%2520with%2520File%2520System%2520Access%2520API.html)). Users report the native saver asks for permission again every time the file is reopened ([forum](https://talk.tiddlywiki.org/t/tw5-major-updates-to-chromium-native-file-system-saver-plugin/2288)). It passes the corporate bar, but it would change your workflow rather than improve it.

**Feather Wiki** is a 55.6 KB self-replicating HTML file under the **AGPL-3.0** license, last updated July 2026. It saves by downloading a new copy or by a PUT to a WebDAV server; no File System Access write-back was found ([Codeberg](https://codeberg.org/Alamantus/FeatherWiki)). It is smaller than Northern Lights and passes the bar, but like TiddlyWiki it keeps content inside itself.

**Markdeep** and **TeXMe** are the math specialists. Markdeep renders LaTeX with equation numbering and ASCII-art diagrams from a double-clicked `.md.html` file in any browser, Firefox and Safari included. If neither a local script nor the internet is available, it falls back to plain text ([Markdeep](https://casual-effects.com/markdeep/)). TeXMe renders Markdown plus MathJax LaTeX. It loads from jsDelivr by default and works offline only if you host TeXMe, marked and MathJax yourself ([TeXMe](https://github.com/susam/texme)). Both are document formats, not tools: they have no editor, no saving, no tabs and no folders. They pass the bar only after you vendor their scripts, at which point they are no longer "download one file and go".

The newer entrants turn out to be thinner than their marketing says. **EdgeMD Viewer** writes back to the original `.md` via the File System Access API and has a pleasant Zen mode. But it advertises "Zero Dependencies" while **loading marked.js and DOMPurify from cdnjs**. It also has no dark mode and only 2 commits ([GitHub](https://github.com/0xedgelessblade/edge-md-viewer)). That makes it a cautionary example: one could not verify Kapur Markdown Editor's similar "zero dependencies, works offline" claim, which appears only in a directory listing ([localhtmltools](https://localhtmltools.lachlanallison.com/tool/kapur-markdown-editor/)). **orz-mdhtml** has the richest feature list here: KaTeX, Mermaid, charts, 11 themes and a CodeMirror editor. But it needs Node 18+ to generate files. Its own docs say "self-contained means a single file, not offline use", and they warn that each file runs embedded JavaScript ([SKILL.md](https://cdn.jsdelivr.net/npm/orz-mdhtml@0.9.3/orz-mdhtml-skills/SKILL.md)). It also re-serialises the whole document on save, which gives up exactly the line-level diff discipline Northern Lights is built around.

## Hosted editors and extensions win on features, then fail the deployment test

**vscode.dev** is the strongest browser alternative for anyone whose main job is editing. On Chrome and Edge it opens a local folder through the File System API and saves files in place. Its Markdown support is "nearly identical to desktop" ([VS Code for the Web](https://code.visualstudio.com/docs/setup/vscode-web)). It is clearly better for multi-cursor editing, search and replace across a folder, and git commits via github.dev. It is worse as a reader: there are no readability controls and no editing in the rendered view. Mermaid and math in the web build's preview were not verified. Corporate verdict: **borderline**. It is a first-party Microsoft origin that many networks already allow. But the docs say nothing about offline behaviour or web telemetry. Uncommitted work lives in browser storage, and Settings Sync can send data to Microsoft services ([VS Code for the Web](https://code.visualstudio.com/docs/setup/vscode-web)). A GitLab report shows the VS Code-based Web IDE calling an external URL and failing on air-gapped instances ([GitLab #414493](https://gitlab.com/gitlab-org/gitlab/-/issues/414493)).

The rest of this group fails Northern Lights' core requirement. **StackEdit** has 23K stars and KaTeX plus Mermaid, but it has not been pushed since **July 2023**, and its last release dates from 2019 ([GitHub API](https://api.github.com/repos/benweet/stackedit)). It keeps files in browser storage with cloud sync rather than saving in place. **Dillinger** is active (push June 2026) but works by import, export and OAuth cloud sync, with no File System Access support and no privacy statement on its site ([dillinger.io](https://dillinger.io/)). **HedgeDoc, HackMD and SilverBullet** are server-backed by design. They win only on real-time collaboration ([HedgeDoc](https://github.com/hedgedoc/hedgedoc)). A long tail of 2025–2026 File System Access apps, such as Accrete (LaTeX, PWA), Markdown Studio (Mermaid) and mdread, do save in place. But the main survey of them was written by a competitor ([NoteLoom, vendor](https://noteloom.cc/blog/browser-based-local-first-markdown-editors/)), and the ones on GitHub have 0 to 66 stars. Any of them is code hosted by an unknown person that can change without notice, so none would pass an IT risk review.

**Browser extensions** beat Northern Lights where it is weakest as a viewer. **MarkView** (20K users, 5.0 stars, updated September 2026) adds KaTeX, PlantUML, Graphviz and WaveDrom, DOCX export, slides, annotations, and **full-text search across a folder** ([Chrome Web Store](https://chromewebstore.google.com/detail/cfopbpknalachedpcddhgbgjoigklien)). simov's **Markdown Viewer** (500K users) offers MathJax, a choice of parser and more than 30 themes. Its store listing has not been updated since May 2024 ([Chrome Web Store](https://chromewebstore.google.com/detail/markdown-viewer/ckkdlimhmcjmikdlpkmbgfkaikojcbjk); [GitHub](https://github.com/simov/markdown-viewer)). Extensions also open a `.md` file at its own file:// URL, so relative images resolve without a "connect folder" step. But **none of the five leading extensions edits or saves back to the source file**. Each needs an install plus a second grant: the off-by-default "Allow access to file URLs" toggle. In locked-down organisations, Edge's `ExtensionInstallBlocklist = *` with an allowlist makes every extension an admin decision ([Microsoft Learn](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-manage-extensions-policies)). MarkView also asks for host permissions on any site, and one aggregator flags this as high-risk ([ExtScope](https://extscope.org/extension/cfopbpknalachedpcddhgbgjoigklien)). Extensions fail the strict bar by definition.

## Installed apps set the feature ceiling (all require installation)

These are reference points only. **Every app below requires installing an executable** and would need IT approval under the stated bar. **Typora** ($14.99) offers true inline WYSIWYG, MathJax, Mermaid and export to DOCX, LaTeX and EPUB ([typora.io](https://typora.io/)). But it has a documented history of silently rewriting files that were never edited (issue #750, which came back after a fix) ([typora-issues #750](https://github.com/typora/typora-issues/issues/750)), and it has no built-in lint ([Typora support](https://support.typora.io/Markdown-Export)). **Obsidian** has three editing modes and a large plugin directory. Its plugins "may generate network traffic outside Obsidian and GitHub's control", and it has no official portable build ([Obsidian security](https://obsidian.md/help/teams/security); [forum](https://forum.obsidian.md/t/obsidian-run-in-portable-mode/915)). **Zettlr** has the strongest academic stack, with LaTeX, Mermaid, Pandoc export and Zotero citations. A PortableApps build exists, but it is still an executable ([zettlr.com](https://www.zettlr.com/); [PortableApps](https://portableapps.com/node/82182)). **MarkText** shipped its first release in four years in May 2026, so its revived maintenance is unproven ([Star History](https://newsletter.star-history.com/p/star-history-monthly-standalone-markdown-editor-may-2026)). **VS Code desktop** is the closest match to Northern Lights' source-first, git-friendly model. It has built-in KaTeX, Mermaid, workspace header search and link refactoring, but it needs an extension for spellcheck ([VS Code Markdown docs](https://code.visualstudio.com/docs/languages/markdown)).

Two findings from this tier support Northern Lights' design. First, rich-text editors rewrite Markdown you did not touch. Joplin's own docs list the conversions: reference links become inline, empty table headers are added, and HTML can be lost ([Joplin Help](https://joplinapp.org/help/apps/rich_text_editor)). That makes Northern Lights' "splice only the edited lines" a real differentiator, not a minor feature. Second, Mermaid is now standard in every serious tool, so Northern Lights' offline Mermaid gives it parity, not an edge. Math has become standard in the same way, and that is where Northern Lights falls behind.

## Math is the gap that matters, and Northern Lights shares one policy risk

The gaps in Northern Lights, ranked by how often they decide the comparison:

1. **Math rendering.** This gap shows up in every category. Markdeep, TeXMe, orz-mdhtml, probably TiddlyWiki, StackEdit, MarkView, simov's viewer, Markdown Preview Plus, Typora, Zettlr and VS Code all render LaTeX or KaTeX. Anyone with equations in their documents will rule Northern Lights out on this alone. Vendoring KaTeX would close it without breaking the offline model, the same way Mermaid is already vendored.
2. **Search across files.** MarkView offers it within a single browser tab, and vscode.dev and VS Code have it built in. Northern Lights already has connect-folder, so the groundwork exists.
3. **Spellcheck.** This gap is common: VS Code core lacks it too. Chrome's native spellcheck may already work inside Northern Lights' edit boxes, but that was not verified.
4. **Relative images and opening friction.** Extensions get relative images for free by living at the file's own URL.
5. **DOCX export, true WYSIWYG and plugins.** These matter less for a tool that reads first, and DOCX would be hard to add without breaking the single-file model.

One thing Northern Lights does **not** escape: Edge's `DefaultFileSystemWriteGuardSetting = 2` blocks every site from requesting write access ([Microsoft Learn](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-browser-policies/defaultfilesystemwriteguardsetting)). That would disable saving in place for Northern Lights, vscode.dev and every File System Access app alike, though viewing would still work. Blocking file:// pages outright is less likely: Microsoft says `URLBlocklist` "doesn't work as expected with file://\* wildcards" ([Microsoft Learn](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-browser-policies/urlblocklist)). It is not known how often enterprises actually set the write guard to 2. In-place saving on Firefox or Safari is a gap for every candidate, not just Northern Lights, because the File System Access API is Chromium-only ([Chrome Developers](https://developer.chrome.com/articles/file-system-access/)).

## Conclusion

The research changes the question. The question is not whether a better browser tool exists. It is that Northern Lights occupies a niche that no other maintained tool targets: a viewer for real `.md` files that reads first, edits without rewriting untouched lines, and needs no install or network. The tools nearest to it each give up one of those properties. Wikis drop the real `.md` files. Hosted editors and EdgeMD drop "no network". Extensions drop editing and "no install". Desktop apps drop "nothing executable". Northern Lights' weakest point is not features but trust signals: it is one person's project, while TiddlyWiki, vscode.dev and MarkView have communities, store badges or vendor backing. In a corporate review, a single file that someone can inspect, with no update channel, partly makes up for that.

Adding vendored KaTeX would remove the single most common reason someone would choose a competitor. Search across a connected folder would remove the second. Beyond those two, the features Northern Lights lacks mostly belong to knowledge-base or publishing tools, and copying them would cost the simplicity that makes it pass the bar in the first place. The open questions to check before relying on these conclusions: whether vscode.dev works offline, and how often enterprises set the File System Access write guard to block.
